**Unfinished Tasks**:

We didn't start User Story 3- 19 for this sprint as we wanted to focus on the core functionalities of the application for  this sprint to get everything set up and running.This allowed us to ensure that the main framework, environment setup, and basic system interactions were fully implemented and running correctly before expanding to additional features. The User Stories we didn't start focused more on additional features such as profile creation,reward system,carbon footprint tracker etc. 


**Practices to continue**: 

Using Trello to manage user stories and tasks.

Holding short check-in meetings to discuss any issues 

Regular commits in respective branches  on GitHub after task completion.

Create dedicated branches for each feature to prevent merge conflicts.


**Practices to use in future sprints**: 

Add code reviews before merging pull requests.
Add a way to encrypt user data to avoid any security issues
Use a SQL Database or another software to manage backend 

**Harmful practices**: 

Stop using the main branch in github for adding new user stories and pushing untested or incomplete code onto main
Vague commit messages , as well as leaving description blank
Merging and doing pull requests on github without communication with the team
Don't hard code values, let user input values. 

**Best/Worst Experience**

 The best experience for the team during this sprint was getting both the GUI’s to work properly which were Passenger and CampusCommute.  

The worst experience for the team during this sprint was we had some setup problems in Eclipse and GitHub, especially with managing branches and file paths. We fixed these by re-importing the project and using the same workspace setup for everyone. Also by using proper branch name conventions based on user stories, so that each branch represented a respective user story feature.
