## **Completed Work**

 During this final sprint, we completed several important features that improved the core flow of our app. We finished the Ratings feature (US 4), which lets users rate rides. We also built the In-App Chat (US 5), allowing passengers and drivers to message each other. After that, we completed the Payment system (US 6), which handles ride payments in a simple and secure way. Lastly, we added the Weather feature (US 19), which shows weather details during the ride.
We also completed supporting features such as Google Maps (US 13), Carbon Footprint (US 12), and Lost & Found (US 16). These features helped make the app more complete and added more tools for the users.

---

## **Unfinished Tasks**

In this sprint, we were unable to finish the following user stories:

- User Story 14 :Ride Cancellation Policy

- User Story 18 : Reward & Points System

- User Story 11 : Carpool Scheduling (Recurring Rides)

User Story 11 was not completed because it was out of scope for our project. Recurring rides require automated scheduling and more advanced backend timers that we did not plan to build.

User Story 14 and User Story 18 were not done because we ran out of time. Our team had multiple blockers from other classes, including tests and assignments, which limited how much work we could contribute near the end. These two features also required additional backend logic, so we focused on completing the main flow instead.

---

## **Practices to Continue**

If we continued development, these are the practices we would keep using because they worked well:

- Regular check-ins to solve technical blockers quickly.  
- Using Trello for managing user stories and workflow.  
- Maintaining clean Git workflows with feature-specific branches.  
- Testing backend endpoints and UI screens right after updates.

---

## **Practices to Use in Future Sprints**

Even though this was the final sprint, these are practices we would add if the project continued:

- Sync branches more frequently to avoid outdated or conflicting code.  
- Add proper exception logging to help debug backend connection issues.  
- Strengthen team code reviews to avoid issues like invalid constructors or mismatched methods.

---

## **Harmful Practices to Stop**
- Pushing untested GUI or backend changes directly to `main` or `dev`.  
- Editing other team members’ GUI files without communication.  
- Working on large user stories alone without providing updates.  
- Hardcoding placeholder values such as `"N/A"` in production logic.
