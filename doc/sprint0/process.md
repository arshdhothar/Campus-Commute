Team Organization (How did you organize the team? Which tools did you use, if any?):

Our team is organized around a collaborative structure where all members share equal responsibility for the project. We have not assigned rigid roles for anybody but plan on leveraging our individual strengths and interests to assign parts. For example, if a member has more front-end experience they will lead interface discussions, while those with stronger back-end experience will focus on API and database design. Along with this, we have one member that oversees sprint planning, ensures deadlines are met and attempts to coordinate meetings to his best ability.

The three main tools we use are Discord, GitHub, and Trello. We use Discord for communication. This includes planning and attending meetings, as well as quick communication that might be necessary throughout the project. We use GitHub for version control and will use it as a code repository later in the project. Lastly, we use Trello for managing our Product Backlog, visualizing user stories and tracking the progress of our tasks.

Decision Making (How did you make decisions?): 

All major decisions are made collaboratively through group discussions on Discord. Any small decisions that don’t need to be discussed can be dealt with individually. If a member is unsure about the severity of the decision they are making we have agreed to discuss it with each other in case. If there is any conflict when discussing these changes, we have agreed to use a majority vote approach. Until all group members are not consulted a major change will not be made. When minor changes are made the member should notify others in the group to keep everybody informed and involved.

Prioritizing User Stories (How did you define priority and/or points of user stories? How many rounds of voting (on average) did you need to come to a consensus for the point estimate? : 

We prioritized our user stories based on the following criteria, ordered by importance:
Core Functionality: Stories that deliver the fundamental value proposition are prioritized first. This includes user story 1: Ride Posting and user story 2: Ride Request. This ensures that we build the essential features that deliver value to the user and form the core of our application.
Safety and Verification: Stories related to security and user verification are prioritized immediately after core functionality. This includes user story 3: Safety and Verification. These features must be included for a trusted campus app and are necessary for the secure foundation to validate the Core Functionality.
Risk Mitigation: Features involving new or complex technologies are prioritized next to reduce the technical complexity of the project.
Enhancement: Stories that enhance the user experience are the next priority. This includes user story 4: Ratings and Feedback System.

Meetings (How frequently did you meet?) : 

We meet once a week on Discord to discuss the progress we have made within the past week and discuss what our next steps are. In this meeting all members are free to ask questions or bring up anything needed. If a meeting cannot be planned for that week, a small discussion is done using Discord messaging.

Next Phase (What lessons should you take forward to the next phase?):

A lesson we will take forward is to hold a meeting earlier in the sprint phase so everybody is assigned tasks and given adequate time to work on their part. This also allows them to reach out for help if necessary
Another lesson is the Product Backlog document must be continuously refined and reprioritized as we gain more insight during development.
We also realized we should use Trello more efficiently to track our progress and make sure tasks are completed on time.
