## **Completed Work**
We implemented several key features this sprint. The Emergency Assistance system was added, including an always-visible emergency button that sends alerts directly to the backend. A full Ride History feature was implemented so users can view past trips. Profile features were expanded, allowing users to edit their profile, upload photos, and view all personal details on a dedicated screen. Notification settings were added so users can control which alerts they receive. Emergency contact information is now stored in user profiles, and campus map integration was introduced to show pickup/drop-off locations with directions.

## **Practices to Continue**
- Regular check-ins to solve technical blockers quickly.  
- Using Trello for managing user stories and workflow.  
- Maintaining clean Git workflows with feature-specific branches.  
- Testing backend endpoints and UI screens right after updates.

---

## **Practices to Use in Future Sprints**
- Sync branches more frequently to avoid outdated or conflicting code.  
- Add proper exception logging to help debug backend connection issues.  
- Strengthen team code reviews to avoid issues like invalid constructors or mismatched methods.

---

## **Harmful Practices to Stop**
- Pushing untested GUI or backend changes directly to `main` or `dev`.  
- Editing other team members’ GUI files without communication.  
- Working on large user stories alone without providing updates.  
- Hardcoding placeholder values such as `"N/A"` in production logic.

---

## **Best / Worst Experience**

### **Best Experience**
Seeing all major features like emergency alerts, profile customization, ride history, and backend integration work smoothly together for the first time. It made the app feel like a real connected system.

### **Worst Experience**
Dealing with Git conflicts, outdated branches, and merge issues, especially when multiple people were editing UI and backend files at the same time.
